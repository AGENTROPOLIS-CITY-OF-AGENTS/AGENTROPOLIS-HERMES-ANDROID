AGENTROPOLIS HERMES Android

Android mobile console for Hermes and Agentropolis. Connects to self-hosted hermes-webui for sessions, skills, memory, tasks, files, and operator approvals.

View repository Install

CANARY. Everything documented here is a canary lane. The phone is a supervision surface, not the authority root. Do not grant broad credentials, wallet-signing authority, or production secrets to this surface.

Overview

The Android application is a control and observation surface for Hermes runtimes. It must not become an unbounded authority source merely because it can reach a Hermes runtime.

Mission Control

Approve, reject, pause, or revoke agent work; inspect mandates, capabilities, artifacts, and receipts.

Read-only by default

New runtime connections start read-only. Backend identity must match the registered identity; mismatches are rejected.

Receipts required

Every mobile-triggered action must produce a correlated receipt. Consequential actions need signed, scoped, time-bounded approval.

Install

The repository ships a runtime adapter that wraps the community Android compatibility runtime (Termux + Termux:X11 + Ubuntu PRoot + source-built Hermes Desktop) without copying its implementation into the AGENTROPOLIS authority surface.

From the Termux host shell

bash runtime-adapters/hermes-desktop-android/install.sh

Verify the pinned release without installing

bash runtime-adapters/hermes-desktop-android/install.sh --verify-only

The wrapper downloads the upstream release installer and checksum, verifies the checksum, and passes the pinned Hermes revision from upstream.lock. Upstream releases are not followed automatically.

Security warning. The compatibility lane runs Electron with --no-sandbox inside a root PRoot guest. Android still confines Termux as an application, but Chromium defense-in-depth is reduced. Wireless ADB is a separate optional bridge: it is not enabled by the installer and remains behind a short-lived explicit capability lease.

Not granted by installation

  • unrestricted ADB
  • wallet access
  • production secrets
  • repository writes
  • deployment authority
  • permanent capabilities

Details: runtime-adapters/hermes-desktop-android/README.md.

AGENTROPOLIS EDGE

Mobile and low-power execution profile. The phone controls the city without being required to run the city; heavy inference and background swarms are routed away from the device unless a verified device profile permits them.

docs/AGENTROPOLIS-EDGE.md

Buzz integration

The console acts as the mobile Mission Control surface for Buzz-coordinated Hermes work: review task threads, approve or revoke, and read receipts. The relay URL defines the active community; nothing crosses communities automatically.

docs/HERMES_BUZZ_MOBILE_INTEGRATION.md

Acceptance gates before promotion

  • pinned upstream release and Hermes commit; checksum verification before install
  • backend identity displayed and verified; read-only first connection
  • no automatic ADB enablement
  • signed approval for writes, merges, publishing, and deployment
  • receipt correlation for every mobile-triggered action
  • stop, revoke, and quarantine tested; telemetry visible
  • canary-device report attached

Mobile convenience may not weaken the same authority and evidence rules enforced by desktop Mission Control.
